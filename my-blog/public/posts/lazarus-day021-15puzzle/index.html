15パズルの作成に挑戦 - Day21

Lazarusチャレンジ21日目です。今回は、15パズルの作成に挑戦しました。15パズルは、1から15までの数字が書かれたタイルをスライドさせて、正しい順序に並べるパズルゲームです。Lazarusで作る題材として、シンプルで分かりやすいパズルゲームです。

今回の目標

今回作成する15パズルアプリとして、以下の機能を実装することを目指しました：

  • TButton 16個: 0-15のTagで位置管理（0は空白）
  • 4×4配列: パズルの状態を管理する2次元配列
  • シャッフル機能: 完成状態から合法手のみでランダムにシャッフル
  • 移動ロジック: クリックしたボタンが空白の隣なら移動
  • クリア判定: 1-15の順序で完成か判定し、完成時にメッセージ表示

15パズルとは？

15パズルは、1から15までの数字が書かれたタイルをスライドさせて、正しい順序に並べるパズルゲームです。

基本ルール

  • 4×4の盤面: 16個のマス（15個のタイル + 1個の空白）
  • タイルの移動: 空白の隣にあるタイルだけが移動できる
  • 目標: 1から15までを順番に並べる
  • シャッフル: 完成状態から合法手のみでランダムに移動してシャッフル

LazManagerを使ったプロジェクト作成

まず、LazManagerを起動して、プロジェクト名に「day021_15」と入力し、プロジェクトを作成しました。

「Cursor」ボタンを押してCursorを起動し、プロジェクトフォルダを開きました。

Cursorへのプロンプト投入

15パズルアプリの開発は、Cursorに直接プロンプトを投入して進めました。

プロンプト: 15パズルの作成

Lazarusで15パズルを作る。
TButton 16個、Tagで位置管理。
4×4配列でロジック管理。
シャッフルは完成状態から合法手のみ。
クリア判定あり。
完全なForm1.pasを書いて。

AIが実装した内容：

  • TButton 16個: 0-15のTagで位置管理（0は空白）
  • 4×4配列: Puzzle[0..3, 0..3]で状態管理
  • 合法手のみのシャッフル: 完成状態から1000回のランダム移動でシャッフル
  • クリア判定: IsSolvedで1-15の順序を確認
  • 移動ロジック: クリックしたボタンが空白の隣なら移動

実装のポイント

データ構造

type
  TForm1 = class(TForm)
  private
    // パズルの状態を管理する2次元配列（4×4）
    Puzzle: array[0..3, 0..3] of Integer;
    
    // 空白の位置
    EmptyRow, EmptyCol: Integer;
    
    // 16個のボタン
    Buttons: array[0..15] of TButton;
  end;
  • Puzzle: パズルの状態を管理する2次元配列（0は空白、1-15はタイル）
  • EmptyRow, EmptyCol: 空白の位置を管理
  • Buttons: 16個のボタンを配列で管理

主な機能

  1. FormCreate: 16個のボタンを生成し、Tagで位置管理
  2. InitializePuzzle: 完成状態で初期化後、シャッフル
  3. ButtonClick: クリックされたボタンが合法手なら移動
  4. IsValidMove: 空白の上下左右かチェック
  5. MoveTile: タイルを空白位置に移動
  6. IsSolved: 1-15の順序で完成か判定
  7. CheckWin: 完成時にメッセージ表示し、再シャッフル
  8. ShufflePuzzle: 合法手のみでランダムに1000回移動

ビルドと実行

Cursorで実装が完了した後、Lazbuildでビルドを実行しました。

C:\Lazarus\Lazbuildでビルド

ビルドが成功し、実行ファイル Day021_15.exe が生成されました。

しかし、実行ファイルを起動すると、Formを開いてもボタンが表示されない問題が発生しました。

発生した問題：ボタンが表示されない

実行ファイルはできましたが、Formを開いてもボタンが表示されず、灰色の画面のままという問題が発生しました。

問題の詳細

最初は、以下のような原因を疑いました：

  1. フォームサイズが小さすぎる: ボタンがフォーム外に配置されている
  2. ボタンのParentが設定されていない: Btn.Parent := Self; が抜けている
  3. ボタンのVisibleがFalse: ボタンが非表示になっている
  4. UpdateButtonsのロジックが間違っている: ボタンの位置更新が正しくない

試行錯誤

Cursorに「ボタンが表示されない」と報告すると、AIは以下の修正を試みました：

  1. LFMファイルのフォームサイズを修正: 320×240 → 400×450
  2. ボタンの表示を明示: Btn.Visible := True を追加
  3. UpdateButtonsのロジックを修正: パズルの状態に基づいてボタンの位置を更新
  4. 16個のボタンを固定位置で作成: テキスト（Caption）のみを更新する方式に変更

しかし、まだボタンが表示されませんでした。

問題の原因：FormCreateが呼び出されていない

試行錯誤を続けているうちに、問題の原因が判明しました。

AIのコードは正しかったのですが、FormCreateが呼び出されていないだけでした。

つまり、LFMファイルでFormCreateイベントが紐づけられていなかったことが原因でした。

解決方法：IDEでフォームをダブルクリック

問題を解決するには、Lazarus IDEでフォームをダブルクリックして、FormCreateイベントを紐づける必要がありました。

  1. Lazarus IDEを起動: プロジェクトファイル（.lpi）を開く
  2. フォームをダブルクリック: Unit1.pasのコードが開く
  3. FormCreateイベントが自動的に紐づけられる: LFMファイルにOnCreateイベントが追加される

これで、FormCreateが正しく呼び出されるようになり、ボタンが表示されるようになりました。

アプリの現状

現在のアプリの状態：

  • ✅ ボタンの表示: 16個のボタンが正しく表示される
  • ✅ パズルの初期化: 完成状態からシャッフルして開始
  • ✅ タイルの移動: クリックしたボタンが空白の隣なら移動
  • ✅ クリア判定: 1-15の順序で完成か判定し、完成時にメッセージ表示

学んだこと

Day21の開発を通じて、以下のことを学びました：

LFMファイルとイベントの紐づけ

  • LFMファイル: Lazarusのフォーム定義ファイル（.lfm）には、フォームのプロパティやイベントの紐づけが記録される
  • イベントの紐づけ: コードでイベントハンドラを実装しても、LFMファイルに紐づけが記録されていないと、イベントが呼び出されない
  • IDEでの紐づけ: Lazarus IDEでフォームをダブルクリックすると、FormCreateなどのイベントが自動的に紐づけられる

FormCreateの重要性

  • FormCreate: フォームが作成されたときに呼び出されるイベント
  • 初期化処理: ボタンの生成やデータの初期化など、フォームの初期化処理はFormCreateで行う
  • イベントの呼び出し: LFMファイルにOnCreateイベントが紐づけられていないと、FormCreateが呼び出されない

AI開発の課題

  • AIが生成したコード: Cursorが生成したコードは正しかったが、LFMファイルの設定が不完全だった
  • IDEとの連携: コードだけでなく、IDEでの設定も重要
  • デバッグの重要性: 実行ファイルはできたが、期待通りの動作をしない場合、IDEでの確認が必要

デバッグのアプローチ

  • 段階的な確認: データが正しく初期化されているか、イベントが正しく紐付いているか、描画が正しいタイミングで実行されているかを確認する必要がある
  • IDEでの確認: コードだけでなく、IDEでの設定（LFMファイル）も確認する必要がある
  • 問題の特定: ボタンが表示されない場合、FormCreateが呼び出されているかを確認する

  3. ボタンが表示されない問題: Formを開いてもボタンが表示されず、灰色の画面のままという問題が発生

  4. 試行錯誤: フォームサイズ、ボタンのParent、Visible、UpdateButtonsのロジックなどを修正したが、まだ改善しなかった

完成した15パズルアプリについて

完成した15パズルアプリは、1から15までの数字が書かれたタイルをスライドさせて、正しい順序に並べるパズルゲームです。16個のボタンが正しく表示され、クリックしたボタンが空白の隣なら移動し、1-15の順序で完成か判定し、完成時にメッセージ表示する機能が動作します。
