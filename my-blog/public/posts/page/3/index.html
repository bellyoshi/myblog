2048ゲームの作成 - Day18

Lazarusチャレンジ18日目です。今回は、2048ゲームを作成しました。4×4のマス目で同じ数字のタイルを合体させて、最終的に「2048」を作るパズルゲームです。

今回の目標

今回作成する2048ゲームは、以下の機能を実装することを目指しました：

  • 新タイル生成: 移動できたときのみ、空マスに新タイルを生成（90%で2、10%で4）
  • 勝利条件: 2048が出現したら勝利
  • ゲームオーバー: 全方向に移動不能になったら終了
  • Canvas描画: 美しい色分けでタイルを表示

2048ゲームとは？

2048は、4×4のマス目の中で、同じ数字のタイルを合体させて最終的に「2048」を作るパズルゲームです。

基本ルール

  • 初期状態: 2または4のタイルが2個ランダムに出現
  • 操作: 上下左右キーで盤面をスライド
  • 動きの仕組み:
    • 全タイルが指定方向に詰められる
    • 同じ数字がぶつかると合体（2 + 2 → 4、4 + 4 → 8...）
    • 合体は1ターンにつき1回のみ
  • 移動後: 空いているマスに2（高確率）か4（低確率）が1つ出現
  • 終了条件:
    • 2048を作ったら勝利
    • 動かせなくなったらゲームオーバー

暗号化テキストエディタの作成 - Day17

Lazarusチャレンジ17日目です。今回は、暗号化テキストエディタを作成しました。DCPcryptパッケージを使用して、AES-256アルゴリズムでテキストを暗号化・復号化できるエディタを実装しました。

今回の目標

今回作成する暗号化テキストエディタは、以下の機能を実装することを目指しました：

  • 暗号化保存: テキストを暗号化してテキストファイルとして保存
  • 復号化読み込み: 暗号化されたファイルをパスワードで復号化して表示
  • 通常のテキストファイル: メモ帳などで開くと暗号化された文字列として表示
  • AES-256暗号化: 強固な暗号化アルゴリズムを使用
  • Base64エンコード: バイナリデータをテキスト形式で保存

LazManagerを使ったプロジェクト作成

まず、LazManagerを起動して、プロジェクト名に「day017_CryptEditor」と入力し、プロジェクトを作成しました。

「Cursor」ボタンを押してCursorを起動し、プロジェクトフォルダを開きました。

パッケージのインストール - はまった点

暗号化機能を実装するために、DCPcryptパッケージをインストールする必要がありました。ここで重要な発見がありました。

オンラインパッケージの2段階インストール

オンラインからパッケージをインストールする場合、2段階の手順が必要であることが分かりました：

  1. Lazarus自体へのインストール: パッケージマネージャからインストール
  2. プロジェクトへの追加: プロジェクトインスペクタからパッケージを追加

インストール手順

ステップ1: パッケージマネージャからインストール

  1. Lazarusのメニューから [パッケージ] > [オンラインパッケージマネージャ] を開く
  2. DCPcrypt を検索してインストール
  3. Lazarus自体が再コンパイルされ、再起動する

この時点で「インストール完了」と思いがちですが、実はこれだけでは不十分でした。

ステップ2: プロジェクトインスペクタからパッケージを追加

コンパイルを実行すると、「パッケージが見つからない」というエラーが発生しました。

原因は、パッケージをLazarusにインストールしただけでは、個別のプロジェクトで使用できないことでした。

解決方法：

  1. プロジェクトインスペクタを開く（メニュー: [表示] > [プロジェクトインスペクタ]）
  2. プロジェクト名を右クリック
  3. [新規追加] > [新規要件] を選択
  4. インストールしたパッケージ（DCPcrypt）を選択して追加

これで、プロジェクトでDCPcryptパッケージを使用できるようになりました。

学んだこと

  • オンラインパッケージのインストールは2段階: Lazarusへのインストールと、プロジェクトへの追加が必要
  • 再コンパイル・再起動だけでは不十分: パッケージマネージャからインストールして再起動しても、プロジェクトでは使用できない
  • プロジェクトインスペクタが重要: プロジェクトでパッケージを使用するには、プロジェクトインスペクタから明示的に追加する必要がある

倉庫番ゲームの作成 - Day16

倉庫番ゲームの作成 - Day16

Lazarusチャレンジ16日目です。今回は、コンソールアプリケーションとして倉庫番（Sokoban）ゲームを作成しました。GUIアプリではなく、テキストベースのシンプルなパズルゲームを実装しました。

今回の目標

今回作成する倉庫番ゲームは、以下の機能を実装することを目指しました：

  • コンソールアプリケーション: GUIではなく、コンソールで動作するテキストベースのゲーム
  • 倉庫番のゲームロジック: 箱を押してゴールに配置するパズルゲーム
  • マップ表示: テキストベースでマップを表示
  • プレイヤー移動: 矢印キーでプレイヤーを移動
  • 箱の押し: 箱を押して移動させる機能
  • クリア判定: すべての箱がゴールに置かれたらクリア

倉庫番ゲームとは

倉庫番（Sokoban）は、倉庫の中で箱を押して、すべての箱を指定されたマス（ゴール）に運ぶパズルゲームです。

ゲームの特徴：

  • 箱は押せるけど引けない
  • 箱同士・壁はすり抜け不可
  • 一度ミスると詰み状態になることがある
  • だから「先を読む」パズルとして名作

盤面の構成要素：

  • #: 壁（動けない）
  • : 床（移動可能）
  • @: プレイヤー（操作キャラ）
  • $: 箱（押す対象）
  • .: ゴール（置き場所）
  • *: 箱＋ゴール（正解状態）

操作ルール：

  • プレイヤーが上下左右に移動する時：
    • 前が床 or ゴール → そのまま移動
    • 前が箱 → その先が床 or ゴールなら箱を押して移動
    • 前が壁 → 移動不可

クリア条件：

  • ゴールマスの数 ＝ 箱の数
  • すべてのゴールに箱が置かれている

Lazarusチャレンジ15日目です。今回は、数独（ナンプレ）ソルバーアプリを作成しました。Knuth's Algorithm X (Dancing Links)という強力なアルゴリズムを実装し、どんな難問でも一瞬で解けるソルバーを完成させました。

今回の目標

今回作成する数独アプリは、以下の機能を実装することを目指しました：

  • 問題入力モード: 9×9のグリッドに数独の問題を入力できる機能
  • Knuth's Algorithm X (Dancing Links): 最強の数独ソルバーアルゴリズムを実装
  • 解の表示: 別ウィンドウで解を表示する機能
  • 懸賞問題の解決: 新聞の懸賞問題なども一発で解決できる機能

LazManagerを使ったプロジェクト作成

まず、LazManagerを起動して、プロジェクト名に「day015_Sudoku」と入力し、プロジェクトを作成しました。

Cursorへのプロンプト投入

プロンプト1: Knuth's Algorithm X (Dancing Links)の実装

最初のプロンプトでは、数独ソルバーの核心となるアルゴリズムを実装しました。

数独ソルバーをつくる。
Knuth's Algorithm X (Dancing Links)を実装したユニットの作成

AIが実装した内容：

  • TDancingLinksNode: 双方向リンクリストのノード構造

    • 上下左右のリンク
    • 列ヘッダーへのポインタ
    • 行ID（数独ではセル位置と値の組み合わせ）

  • TDancingLinksSolver: Dancing Linksソルバークラス

    • Create: 指定数の列で初期化
    • AddRow: 行を追加（行IDとカバーする列のインデックス）
    • Solve: Algorithm Xで解を探索
    • GetSolution: 解を取得

Algorithm Xとは：

Algorithm Xは、ドナルド・クヌースが提唱した「完全被覆問題（Exact Cover Problem）」を解くためのアルゴリズムです。数独は以下の4つの制約をすべて満たすように数字を配置するゲームですが、これを「行」と「列」の巨大な行列（マトリックス）として表現します：

  • マス制約: 全てのマス（81箇所）に何らかの数字が入る
  • 行制約: 各行（9行）に1〜9が1つずつ入る
  • 列制約: 各列（9列）に1〜9が1つずつ入る
  • ブロック制約: 各ブロック（9個）に1〜9が1つずつ入る

問題2: リセット時のAccess violationエラー
