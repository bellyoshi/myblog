Actba64を開発したbellyoshiさんに50の質問

懐かしの「〇〇に50の質問」形式で、64bit版ActiveBasic互換コンパイラ Actba64 の開発を振り返ってみました。

はじめに・自己紹介

1. まずはお名前（ハンドルネーム）と、その由来を教えてください。

bellyoshi。自分の名前（Yoshi）が響くように。

2. 普段どのような活動（開発・プログラミングなど）をされていますか？

ほとんど趣味の世界ですが、社内で使うアプリも作ったりしています。

3. プログラミングを始めたきっかけと、最初に触れた言語は何ですか？

中学校の時、パソコン室にあった機械で N88BASIC を触りました。

でも、それより前に、小学校の廊下にあったパソコンで Color 2 とか打つと色が変わったりするのを遊んでいたから、それにもN88BASICが入っていたと思います。

4. 「ActiveBasic」と出会った時期や、当時の思い出を教えてください。

高校に入ってC言語をやっていたけど、Cだとグラフィックスを出すのも大変。そんなころに、N88BASIC風に書けるコンパイラーを見つけて感動しました。

5. 数ある開発環境・言語の中で、ActiveBasicのどこに一番魅力を感じましたか？

N88BASIC風で、コンパイルが可能ということ。

Actba64 の誕生

6. 64bit版ActiveBasicコンパイラ「Actba64」を開発しようと思ったきっかけは何ですか？

ActiveBasicのサイトが閉鎖してしまったこと。

7. 構想を練り始めてから、最初のバージョンが動くまでどのくらいの期間がかかりましたか？

Cursorを使った最初のプロトタイプは、exeの出力に注力しました。

1日目に

MessageBox(NULL, "This is message ", "My Yoshi App", MB_OK)

が動くコンパイラ群ができあがり、「これはいける！」と思いました。4日目の prototype4 でセルフホストが可能になりました。

8. 開発環境（OS、エディタ、使用言語、デバッガなど）を教えてください。

もちろん ActiveBasic。バージョンは 4.20 を使っています。最新版の4.24が入手できなくなったため、Vectorからダウンロード可能なv4.20をスタートにしています。

AIは最初はCursorエディターを使っていましたが、いまはClaudeを使用しています。

9. Actba64の設計において、特にこだわったポイントはどこですか？

ActiveBasicで動くプログラムが、可能な限り変更なしで動くこと。ActiveBasic 2.62系もコンパイル可能にしました。

  • -pAB2 オプションで 2.62 系もコンパイル可能
  • ActiveBasic 3 系・4 系はオプションなしでコンパイル可能

10. 本家ActiveBasic（32bit版）の仕様を再現する上で、一番気を使った部分はどこですか？

既存のソースコードを書き換えずに、そのまま通すための互換性維持です。

文字コードをUTF-8にしてしまったので、A系（例えば MessageBoxA）のWin32 APIをそのまま呼ぶと文字化けしてしまいます。そこで、W系を呼ぶラッパを用意しています。

11. 逆に、本家からあえて変更した仕様や、独自に拡張した機能があれば教えてください。

  • 文字コードをUTF-8にした
  • Print "Hello World" と書くとき、#console を省略可能にした
  • メソッドのオーバーライドを可能にした
  • Linuxで動くようにした

など多数。

技術的な話

12. 64bit化（x64アーキテクチャ対応）にあたって、最も苦労した壁は何でしたか？

呼び出し規約が変わったことです。64bit化しつつも32bitでもコンパイル可能にしたため、ASTからIRにするところでのみ分岐するようにしています。

13. 開発中「これは直らないかも……」と頭を抱えた、一番手強かったバグの思い出はありますか？

一度ビルドが壊れると、ActiveBasicでもビルドできなくなって、にっちもさっちもいかない……。結局gitで元に戻しました。

14. 字句解析・構文解析・コード生成などのコンパイラ実装で、一番好きな工程はどこですか？

字句解析くらいなら自分で書けますが、あとはAIに任せています。むしろ、実装よりも構想を練るほうが大事だと思います。

15. 逆に、一番地味で大変だった（二度とやりたくない）工程はどこですか？

ドキュメントの作成（笑）。しかし、継続的にする必要があります。AIは人間が読むドキュメントの作成は苦手な気がします。

16. 開発の参考にした書籍や資料、Webサイトなどはありますか？

いまもActiveBasicのサンプルコードを公開されているサイト（Oriosさん、ifdefさん、shinryoさんのサイト）。それから『入門BASIC -グラフィックスを中心に-』。

17. ポインタやインラインアセンブラ周りの実装で工夫した点はありますか？

アセンブラ周りの仕様や機械語への変換テーブルは、AIと相談しながら泥臭く実装しました。動くバイナリが直接吐き出されるように工夫しています。

18. Windows APIの64bit対応（型サイズの違いなど）を吸収する上で苦労したことは？

QWORD、INT64 の実装。

19. コンパイラの出力するアセンブリや機械語を見て「よし、美しい！」とニヤリとした瞬間はありますか？

Hello Worldの出力サイズが180KBくらいあったんですが、Actba64に不要命令削除オプション -X を追加したところ、9KBくらいになりました。

まだまだ最小のHello Worldではないのですが、小さくなった時には、最初のHello Worldが表示された時より感動しました。

20. Actba64で最初に「Hello, World!」やGUIウィンドウが動いたときの気持ちを教えてください。

「ようやくか」と思いました。Print "Hello World" は結構難しい。MessageBox のほうが、dataセクションに文字列を入れてcallするだけでよいから簡単でした。

開発スタイル

21. 開発中、モチベーションを維持するためにしていたことは何ですか？

対応できるプログラムの数が増えていくのが楽しみ。

22. 開発は主にどの時間帯に作業することが多いですか？（朝型・夜型・休日集中など）

休日と、早朝と夜です。こいつのせいで近頃寝不足気味。

23. コーディング中のお供（飲み物、お菓子、BGMなど）はありますか？

コーヒー。でもおなかが痛くなるので、たくさんは飲めない。

24. 自分の書いた過去のソースコードを見て、ツッコミを入れたくなることはありますか？

ツッコミを入れる前に直す。常にリファクタリングの毎日。

25. 「これだけは譲れない」というプログラミング上の美学やルールはありますか？

動けばいい！ 但し正しく。

公開とユーザー

26. 初めてActba64を公開したときの反応で、印象に残っていることはありますか？

公開したけど、だれも使わんよな。はて、私は何をやっているのか。

27. ユーザーからのバグ報告や要望で、特に嬉しかった・助かったエピソードは？

まだ、日本で一人も使っていないでしょう。

28. Actba64を使って作られた作品やソフトの中で、印象深いものはありますか？

ActiveBasicで作られたソフトが一通り動きます。そして、Actba64もActba64でコンパイルが可能です。

Actba64を除くと、ProjectEditor と rc（リソースコンパイラー） がActba64で作成されました（開発ツール群）。

29. ActiveBasicコミュニティや、往年のN88-BASIC・HSPなどの文化についてどう思いますか？

HSPは知らんが、ABのコミュニティは消滅していると思います。

30. 32bitから64bitへ時代が移り変わる中で、BASIC系言語が果たす役割は何だと思いますか？

BASICの名の通り。初心者にわかりやすく。

31. 今でもActiveBasic（およびActba64）を使い続けているユーザーに共通する魅力は何だと思いますか？

そもそも今使い続けている人はほとんどいないと思いますが……もしいるとしたら、余計なランタイムなしで軽量なネイティブEXEがサクッと作れる快感を知っている人たちだと思います。

32. もし当時の本家ActiveBasic開発者（山本大祐さんなど）に一言伝えるとしたら、何と言いますか？

高校時代からずっとお世話になりました。ActiveBasicのおかげでプログラミングの楽しさを知りました。本家が閉鎖されてからも「どうしても4.20の書き心地のまま使い続けたい」という思いが抑えきれず、勝手に互換コンパイラを作ってしまいました。素晴らしい開発環境を世に出してくださり、本当にありがとうございました！

低レイヤとプログラミング観

33. Actba64以外で、これまで開発した中で思い出深いツールやソフトはありますか？

20年ほど前にActiveBasicで作った「リバーシ」や、ソースコードをHTMLに変換する「AB2HTML」などです。自分の原点のひとつです。ただ、当時のソースは失われてしまいました。

いまなら、AIで10秒で作れる代物ですが。

34. BASIC系以外で、今一番お気に入りのプログラミング言語は何ですか？

TypeScript。

35. 低レイヤ（アセンブリ、OS、コンパイラなど）の世界にハマったきっかけは何ですか？

「動けばいい」の延長線上で、ブラックボックスの中身がどうなっているのか気になったから。PEフォーマットや機械語を直接生成できるようになると、PCを完全に支配している感覚があって面白いです。

36. エラーメッセージの文面やコンパイル速度など、使い心地で意識していることはありますか？

AI（LLM）にコンパイルさせて、エラーを自動修正させることが多いので、人間だけでなくAIが読んで一発で場所と原因を特定できる、シンプルなエラー出力を意識しています。

素顔のbellyoshi

37. 開発に行き詰まったときのリフレッシュ方法は何ですか？

10分体操。

38. プログラミング以外の趣味や、休日の過ごし方を教えてください。

読書。資格の勉強。

39. パソコン歴の中で、一番思い出に残っているマシン（PCやOS）は何ですか？

ActiveBasicに熱中していた頃の、Windows XPあたりのマシン。フリーソフト文化が熱くて、一番いろいろ作っていました。

40. 昔ながらの個人サイト文化（「〇〇に50の質問」やキリ番など）に思い出はありますか？

2000年代半ばに、自分でも「Active Basic By Yoshi」という個人サイトを作ってソフトを公開していました。掲示板や相互リンクなど、当時の空気感は懐かしいですね。

これからのActba64

41. 今後のActba64で、実装してみたい機能やアップデート計画はありますか？

Linuxでも動く部分をさらに増やしたいですね。もうすでに、コンパイラーのセルフホストはできています。

あとは、プロジェクトエディターもLinuxでコンパイルできるようにして、LinuxでGUIも動かせるようにしたいです。

42. 逆に「これはあえて実装しない」と決めていることはありますか？

巨大なランタイムライブラリや、外部DLLへの依存です。単体でサクッと動く、軽量な実行ファイルの吐き出しにこだわっています。

43. これからActba64を触ってみたいという人に、最初におすすめしたい使い方は？

AIに「ActiveBasicの文法でツールを書いて」と頼んで、Actba64でコンパイルして遊ぶのが現代風でおすすめです。

44. 既存の32bit版ActiveBasic資産をActba64へ移行する際のアドバイスをください！

基本的にはそのままコンパイルが可能なのですが、そのまま開発が続けられるかというと難しいかもしれません。

-actba32 オプションを付ければ、32bit版のまま開発できます。

45. いつか作ってみたい「夢のソフトウェア」や「理想のプログラミング言語」はありますか？

WindowsでもLinuxでも、同じソースから依存関係ゼロの極小ネイティブアプリが一発で吐き出せる、究極に軽い開発環境です。

46. AI（LLM）がコードを書く時代になりましたが、コンパイラや言語開発への考え方に変化はありましたか？

GUIのコンパイラーはAIが動かしにくいので、コマンドライン形式にしています。

47. bellyoshiさんにとって「コンパイラを作る」とは一言でいうと何ですか？

失われた開発環境を、自分の手で蘇らせるための手段。

48. あなたにとって「ActiveBasic」とはどんな存在ですか？

時代遅れかもしれないけれど、一番手に馴染む、使い慣れた道具のような存在。

49. ActiveBasic（Actba64）のユーザーの皆さんへ、メッセージをお願いします！

もしこの広い日本のどこかに使っている方が一人でもいたら奇跡です。ぜひバグ報告や感想をください！

50. お疲れ様でした！最後に今の率直な感想をどうぞ！

50問は思ったより長かったですが、開発の振り返りになって面白かったです。ありがとうございました。
