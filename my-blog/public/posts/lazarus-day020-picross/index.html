ピクロス（ノノグラム）の作成に挑戦 - Day20

Lazarusチャレンジ20日目です。今回は、**ピクロス（ノノグラム）**の作成に挑戦しました。ピクロスは、数字をヒントにマスを塗りつぶして絵を完成させるロジックパズルです。Lazarusで作る題材としてめちゃくちゃ相性がいい、ということで挑戦してみました。

今回の目標

今回作成するピクロスアプリとしての初日は最小構成として以下の機能を実装することを目指しました：

  • 10×10固定盤面: TDrawGridを使用して盤面を表示
  • セルの状態管理: 未確定（白）と塗りつぶし（黒）の2状態
  • マウス操作: 左クリックでセルを黒に塗る、もう一度クリックで白に戻す
  • ヒント表示: 行ヒント（左側）と列ヒント（上側）を表示
  • 問題データ: 簡単なレベルの問題データを固定データとして用意（十字型の図形）

ピクロス（ノノグラム）とは？

ピクロスは、数字をヒントにマスを塗りつぶして絵を完成させるロジックパズルです。

基本ルール

  • 縦・横に並んだ数字がヒント: 数字は「連続して塗るマスの数」を表す
  • マスの状態: 未確定（白）、塗る（黒）、空白（×）の3状態
  • 黒の塊同士は必ず1マス以上空く: 連続した数字は別々の塊を表す
  • すべての条件を満たすと絵が完成: ドット絵が浮かび上がる

例（超ミニ）

横ヒント →  [3] [1]
            □ □ □ □ □
縦ヒント ↓
[1]         ■ □ ■ □ □
[2]         ■ □ ■ ■ □
  • [3] → どこかに3マス連続で黒
  • [1 2] → 1マス黒 → 空白 → 2マス黒

完成すると「ハート」「文字」「キャラ」みたいな絵になるのが気持ちいいパズルです。

実装のポイント

データ構造

type

  TForm1 = class(TForm)
  private
    // 盤面の状態を管理する2次元配列（10×10）
    FGrid: array[0..9, 0..9] of TCellState;
    
    // 行ヒントデータ（左側に表示される予定）
    FRowHints: array[0..9] of Integer;
    
    // 列ヒントデータ（上側に表示される予定）
    FColHints: array[0..9] of Integer;
  end;

アプリは起動しましたが、ヒントが表示されない問題が発生しました。

発生した問題：ヒントが表示されない

実行ファイルはできましたが、行ヒント（左側）と列ヒント（上側）が表示されない問題が発生しました。

問題の詳細

Cursorが生成したコードでは、DrawGrid1DrawCellメソッドでヒントを表示しようとしていましたが、実際には表示されませんでした。

Geminiへの相談

ヒントが表示されない問題を解決するため、Geminiにメソッドの書き換えを依頼しました。

Geminiからは以下の修正案が提示されました：

  1. Y座標の計算を修正: TextOutのY座標計算に問題がある可能性
  2. TextRectの採用: TextOutの代わりにTextRectを使用し、TTextStyleで中央揃えを指定
  3. デバッグ用のチェック: FRowHints / FColHintsが空ではないか確認

修正後のコード例

Geminiが提案した修正コードは以下の通りです：

procedure TForm1.DrawGrid1DrawCell(Sender: TObject; aCol, aRow: Integer;
  aRect: TRect; aState: TGridDrawState);
var
  HintText: String;
  TS: TTextStyle;
begin
  with DrawGrid1.Canvas do
  begin
    // テキストスタイルの設定（中央揃え用）
    TS := TextStyle;
    TS.Alignment := taCenter;  // 水平中央
    TS.Layout := tlCenter;     // 垂直中央
    TS.Clipping := True;       // セルからはみ出さない

    // 左側の固定列：行ヒントを表示
    if aCol = 0 then
    begin
      Brush.Color := clBtnFace;
      FillRect(aRect);
      Font.Color := clBlack;
      Font.Style := [fsBold];
      Font.Size := 10;
      
      HintText := FormatHint(FRowHints[aRow - 1]);
      if HintText = '' then HintText := '0';
      
      // TextRectを使用して描画範囲(aRect)内に中央揃えで描画
      TextRect(aRect, aRect.Left, aRect.Top, HintText, TS);
      
      Pen.Color := clGray;
      Rectangle(aRect);
    end
    // 上側の固定行：列ヒントを表示
    else if aRow = 0 then
    begin
      Brush.Color := clBtnFace;
      FillRect(aRect);
      Font.Color := clBlack;
      Font.Style := [fsBold];
      Font.Size := 10;
      
      HintText := FormatHint(FColHints[aCol - 1]);
      if HintText = '' then HintText := '0';
      
      // TextRectを使用して描画範囲(aRect)内に中央揃えで描画
      TextRect(aRect, aRect.Left, aRect.Top, HintText, TS);
      
      Pen.Color := clGray;
      Rectangle(aRect);
    end
    // データセル（盤面）の描画
    else
    begin
      case FGrid[aCol - 1, aRow - 1] of
        csEmpty:  Brush.Color := clWhite;
        csFilled: Brush.Color := clBlack;
        else      Brush.Color := clWhite;
      end;
      
      FillRect(aRect);
      Pen.Color := clGray;
      Rectangle(aRect);
    end;
  end;
end;

修正を適用しても改善しない

Geminiが提案した修正コードを適用しましたが、まだヒントが表示されませんでした。

問題の解決：描画順序の問題

Geminiのコードをもう一度見つめてみると、問題の原因が判明しました。

問題の原因

Geminiが提案したコードでは、以下の順序で描画していました：

  TextRect(aRect, aRect.Left, aRect.Top, HintText, TS);  // ② テキストを描画
  ・・・
  FillRect(aRect);        // ① 背景を塗りつぶす
　・・・
  Rectangle(aRect);        // ③ 枠線を描画
end

これでは**TextRectで文字を描画した後にFillRectで背景を塗りつぶしていた**ため、文字は上書きされて消えてしまっていました。

解決方法：描画順序の修正

正しい描画順序は以下の通りです：

  1. 背景を塗りつぶす（FillRect）
  2. テキストを描画（TextRect）
  3. 枠線を描画（Rectangle）

修正後のコード：

// 左側の固定列：行ヒントを表示
if aCol = 0 then
begin
  // ① まず背景を塗りつぶす
  Brush.Color := clBtnFace;
  FillRect(aRect);
  
  // ② フォント設定
  Font.Color := clBlack;
  Font.Style := [fsBold];
  Font.Size := 10;
  
  // ③ ヒントテキストを取得
  HintText := FormatHint(FRowHints[aRow - 1]);
  if HintText = '' then HintText := '0';
  
  // ④ テキストを描画
  TextRect(aRect, aRect.Left, aRect.Top, HintText, TS);
  
  // ⑤ 最後に枠線を描画（これで枠線が上書きされない）
  Pen.Color := clGray;
  Rectangle(aRect);
end
// 上側の固定行：列ヒントを表示
else if aRow = 0 then
//同様・・・

この順序に修正することで、ヒントが正しく表示されるようになりました！

学んだこと

Day20の開発を通じて、以下のことを学びました：

TDrawGridの固定行・列

  • FixedCols / FixedRows: TDrawGridで固定行・列を設定するには、FixedColsとFixedRowsプロパティを設定する必要がある
  • 描画の分岐: aCol = 0やaRow = 0で固定行・列を判定する際は、FixedColsとFixedRowsが正しく設定されている必要がある

テキスト描画の方法

  • TextOut: 座標を1ピクセル単位で計算する必要がある
  • TextRect: TTextStyleを使用することで、セル内の完璧な上下左右中央揃えが自動的に行われる
  • Y座標の計算: TextOutのY座標は文字の上端（Top）を指すため、中央揃えには計算が必要

デバッグの重要性

  • 問題の特定: 実行ファイルはできたが、期待通りの動作をしない場合、デバッグが必要
  • 段階的な確認: データが正しく初期化されているか、イベントが正しく紐付いているか、描画が正しいタイミングで実行されているかを確認する必要がある
  • コードの見直し: AIが生成したコードでも、人間がもう一度見つめてみることで、問題の原因が判明することがある

描画順序の重要性

  • 描画の順序: Canvasでの描画は、後から描画したものが上に表示される
  • FillRectとRectangle: FillRectで背景を塗りつぶしてしまうと文字が表示されない。AIはこの順番に気が付かないことが多い
  • 正しい順序: 背景塗りつぶし → テキスト描画 → 枠線描画 の順序が重要

AI開発の課題

  • AIが生成したコード: Cursorが生成したコードでも、期待通りの動作をしない場合がある
  • 問題の解決: Geminiに相談しても、提案された修正が必ずしも問題を解決するとは限らない
  • 人間の判断: AIのコードを人間がもう一度見つめてみることで、問題の原因が判明することがある
  • デバッグスキル: AI開発でも、デバッグスキルは重要
