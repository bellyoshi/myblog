# 倉庫番ゲームの作成 - Day16

Lazarusチャレンジ16日目です。今回は、**コンソールアプリケーション**として**倉庫番（Sokoban）ゲーム**を作成しました。GUIアプリではなく、テキストベースのシンプルなパズルゲームを実装しました。

## 今回の目標

今回作成する倉庫番ゲームは、以下の機能を実装することを目指しました：

- **コンソールアプリケーション**: GUIではなく、コンソールで動作するテキストベースのゲーム
- **倉庫番のゲームロジック**: 箱を押してゴールに配置するパズルゲーム
- **マップ表示**: テキストベースでマップを表示
- **プレイヤー移動**: 矢印キーでプレイヤーを移動
- **箱の押し**: 箱を押して移動させる機能
- **クリア判定**: すべての箱がゴールに置かれたらクリア

## 倉庫番ゲームとは

倉庫番（Sokoban）は、倉庫の中で箱を押して、すべての箱を指定されたマス（ゴール）に運ぶパズルゲームです。

**ゲームの特徴：**
- 箱は**押せるけど引けない**
- 箱同士・壁はすり抜け不可
- 一度ミスると**詰み状態**になることがある
- だから「先を読む」パズルとして名作

**盤面の構成要素：**
- `#`: 壁（動けない）
- ` `: 床（移動可能）
- `@`: プレイヤー（操作キャラ）
- `$`: 箱（押す対象）
- `.`: ゴール（置き場所）
- `*`: 箱＋ゴール（正解状態）

**操作ルール：**
- プレイヤーが上下左右に移動する時：
  - 前が床 or ゴール → そのまま移動
  - 前が箱 → その先が床 or ゴールなら箱を押して移動
  - 前が壁 → 移動不可

**クリア条件：**
- ゴールマスの数 ＝ 箱の数
- すべてのゴールに箱が置かれている

## Cursorへのプロンプト投入

倉庫番ゲームの開発は、いくつかのプロンプトに分けて進めました。

### プロンプト1: コンソールで動くテキストベースの倉庫番ゲーム

最初のプロンプトでは、基本的な倉庫番ゲームを実装しました。

```
コンソールで動くテキストベースの倉庫番ゲーム。

const Map: array[0..6] of string = (
  '#######',
  '#     #',
  '# .$@ #',
  '#  .  #',
  '#     #',
  '#######'
);

壁	動けない	#
床	移動可能	
プレイヤー	操作キャラ	@
箱	押す対象	$
ゴール	置き場所	.
箱＋ゴール	正解状態	*
```

**AIが実装した内容：**

- **マップ表示**: 提供されたマップを表示
- **プレイヤー移動**: 矢印キーで移動
- **箱の押し**: 箱を押して移動
- **ゴール判定**: 箱をゴールに置くと `*` に変化
- **クリア判定**: すべての箱がゴールに置かれるとクリア

**操作方法：**
- 矢印キー: プレイヤー移動
- Q: ゲーム終了

### プロンプト2: ビルドの実行

ビルドを実行して動作を確認しました。

```
C:\Lazarus\Lazbuildでビルド
```

最初のビルドでは、配列の要素数が不足しているエラーが発生しました。マップは6行（インデックス0-5）なので、`array[0..6]` を `array[0..5]` に変更する必要がありました。

AIが自動的に修正し、ビルドが成功しました。実行ファイル `day016_Sokoban.exe` が生成されました。

### プロンプト3: 文字化けの問題と英語出力への変更

実行してみると、日本語の文字列が文字化けしていました。

```
文字コードが違うため文字化けしている
===  ?  ｺｫ  ｪ  ｲ  ｼ   ===
    ｽ   ｹ ｳ :   ｢  ｰ  ｭ  ｼ  ｧ ｧｻ   , Q  ｧ ｵ  ｺ
```

最初は、Windows APIでコンソールのコードページを日本語（CP932）に設定する方法を試しましたが、文字化けは解消されませんでした。

最終的に、**すべての日本語文字列を英語に変更**することで解決しました。

```
文字化けは続いている。英語で出力する。Windowsは削除
```

**変更内容：**
- `Windows`ユニットを削除
- すべての日本語文字列を英語に変更:
  - `=== 倉庫番ゲーム ===` → `=== Sokoban Game ===`
  - `操作方法: 矢印キーで移動, Qで終了` → `Controls: Arrow keys to move, Q to quit`
  - `ゴール:` → `Goals:`
  - `おめでとうございます！クリアしました！` → `Congratulations! You cleared the level!`
  - `Enterキーを押して終了...` → `Press Enter to exit...`

これで文字化けは解消され、英語で表示されるようになりました。

### プロンプト4: クリア条件の実装

クリア条件を正しく実装するため、以下の要件を追加しました。

```
ゴールマスの数 ＝ 箱の数
すべてのゴールに箱が置かれている
ShowMessage('CLEAR!');
終了する
```

**AIが実装した内容：**

- **クリア判定の実装**:
  - ゴールマスの数（`Game.GoalCount`）をカウント
  - ゴールに置かれた箱の数（`Game.BoxOnGoalCount`）をカウント
  - `Game.BoxOnGoalCount = Game.GoalCount` のときにクリア判定

- **クリア時の処理**:
  - 「CLEAR!」を表示
  - クリア後、すぐに終了（Enter待ちを削除）

すべてのゴールに箱が置かれたときに「CLEAR!」を表示して終了するようになりました。

## 学んだこと

Day16の開発を通じて、以下のことを学びました：

### コンソールアプリケーションの作成

- **コンソールアプリの特徴**: GUIアプリとは異なり、テキストベースで動作するアプリケーション
- **文字コードの問題**: Windowsのコンソールでは、日本語の文字化けが発生しやすい
- **英語出力の選択**: 文字化けを避けるため、英語で出力する選択も有効

### 倉庫番ゲームの実装

- **シンプルなデータ構造**: 文字列配列でマップを表現できる
- **移動判定のロジック**: プレイヤー、箱、壁の位置関係を適切に判定する必要がある
- **クリア条件**: すべてのゴールに箱が置かれているかを正確に判定する必要がある

### 文字化けの問題と解決

- **文字コードの違い**: Windowsのコンソールは、デフォルトでShift_JIS（CP932）を使用するが、LazarusのデフォルトはUTF-8の可能性がある
- **解決方法**: Windows APIでコードページを設定する方法もあるが、英語出力に変更する方が確実
- **実用的な選択**: 開発時間を考慮すると、英語出力に変更する方が効率的。日本語で出力するのは今後の課題。

### コンソールアプリの利点

- **シンプルさ**: GUIアプリよりもシンプルに実装できる
- **軽量**: リソースをあまり使わない
- **テキストベース**: マップデータを直接コードに書けるため、編集が容易
