# 数独アプリの作成 - Day15

Lazarusチャレンジ15日目です。今回は、**数独（ナンプレ）ソルバーアプリ**を作成しました。Knuth's Algorithm X (Dancing Links)という強力なアルゴリズムを実装し、どんな難問でも一瞬で解けるソルバーを完成させました。

## 今回の目標

今回作成する数独アプリは、以下の機能を実装することを目指しました：

- **問題入力モード**: 9×9のグリッドに数独の問題を入力できる機能
- **Knuth's Algorithm X (Dancing Links)**: 最強の数独ソルバーアルゴリズムを実装
- **解の表示**: 別ウィンドウで解を表示する機能
- **懸賞問題の解決**: 新聞の懸賞問題なども一発で解決できる機能

## LazManagerを使ったプロジェクト作成

まず、LazManagerを起動して、プロジェクト名に「**day015_Sudoku**」と入力し、プロジェクトを作成しました。

「**Cursor**」ボタンを押してCursorを起動し、プロジェクトフォルダを開きました。

## Cursorへのプロンプト投入

数独アプリの開発は、2つのプロンプトに分けて進めました。

### プロンプト1: Knuth's Algorithm X (Dancing Links)の実装

最初のプロンプトでは、数独ソルバーの核心となるアルゴリズムを実装しました。

```
数独ソルバーをつくる。
Knuth's Algorithm X (Dancing Links)を実装したユニットの作成
```

**AIが実装した内容：**

- **TDancingLinksNode**: 双方向リンクリストのノード構造
  - 上下左右のリンク
  - 列ヘッダーへのポインタ
  - 行ID（数独ではセル位置と値の組み合わせ）

- **TDancingLinksSolver**: Dancing Linksソルバークラス
  - `Create`: 指定数の列で初期化
  - `AddRow`: 行を追加（行IDとカバーする列のインデックス）
  - `Solve`: Algorithm Xで解を探索
  - `GetSolution`: 解を取得
  - `CoverColumn`/`UncoverColumn`: 列のカバー/アンカバー
  - `SelectColumn`: 最小サイズの列を選択

**Algorithm Xとは：**

Algorithm Xは、ドナルド・クヌースが提唱した「完全被覆問題（Exact Cover Problem）」を解くためのアルゴリズムです。数独は以下の4つの制約をすべて満たすように数字を配置するゲームですが、これを「行」と「列」の巨大な行列（マトリックス）として表現します：

- **マス制約**: 全てのマス（81箇所）に何らかの数字が入る
- **行制約**: 各行（9行）に1〜9が1つずつ入る
- **列制約**: 各列（9列）に1〜9が1つずつ入る
- **ブロック制約**: 各ブロック（9個）に1〜9が1つずつ入る

**Dancing Links (DLX)とは：**

Algorithm Xを実際にコンピュータで動かす際のデータ構造のことです。双方向連結リストで行列の「1」がある場所だけを上下左右のポインタでつなぎます。探索中、不要になった行や列をリンクから外し、戻るときに再びリンクを繋ぎ直します。このポインタを外したり繋いだりする様子が「踊っている（Dancing）」ように見えることから名付けられました。

このアルゴリズムにより、数独のようなパズルを瞬時に解くことができます。

### プロンプト2: 数独UIの作成

次に、問題を入力し、解を表示するUIを作成しました。

```
数独 UIの作成。
問題入力モード。
テキストボックス：数字の１～9を一文字のみ未入力可能。
9x9個
3x3で線を入れる。

ソルバーボタン
ソルバーを呼び出し、
別のウインドウで解を表示
```

**AIが実装した内容：**

1. **問題入力フォーム（Form1）**
   - 9×9のテキストボックス（TEdit）
   - 数字1-9のみ入力可能（1文字のみ）
   - 3×3の区切り線を黒い太線で表示
   - ソルバーボタン

2. **解表示フォーム（Form2）**
   - 別ウィンドウで解を表示
   - 9×9のパネルで解を表示（読み取り専用）
   - 3×3の区切り線を表示
   - 閉じるボタン

3. **数独ソルバー（SudokuSolver.pas）**
   - Dancing Linksアルゴリズムを使用
   - 数独の問題を正確被覆問題に変換
   - 324列の制約（セル、行、列、ボックス）

4. **機能**
   - 入力検証：数字1-9のみ、1文字のみ
   - ソルバー実行：ボタンクリックで解を探索
   - 解の表示：別ウィンドウで解を表示

## Geminiに相談して学んだこと

数独アプリを作成する過程で、Geminiに数独の問題生成アルゴリズムについて相談しました。その結果、重要な発見がありました。

### 問題を作るよりも解く方が簡単

Geminiとの会話を通じて、**数独の問題を作るよりも、問題を解く（特報）方がはるかに簡単**だということが分かりました。

**問題を作るプロセス：**

1. **完成した盤面（解）の生成**: バックトラッキング法でルールを満たした正解盤面を作る
2. **数字を削って問題を作成**: 完成した盤面から、少しずつ数字を消していく
3. **唯一解の確認**: 数字を消すたびに、ソルバーを呼び出して「唯一解（答えが1つだけ）」が維持されているかチェックする
4. **繰り返し**: 答えが複数できてしまったら、そのマスを元に戻す。これを目標の難易度（ヒント数）に達するまで繰り返す

つまり、**問題を作るにはソルバーを何回も呼び出して有効な問題かを確認する必要がある**のです。1つの問題を生成するために、何百回、何千回とソルバーを呼び出す必要があります。

**問題を解くプロセス：**

一方、問題を解く場合は、ソルバーを1回呼び出すだけで済みます。Algorithm X (Dancing Links)を使えば、どんな難問でも瞬時に解くことができます。

### 懸賞の問題も一発で解決

このソルバーの強力さを実感したのが、**新聞の懸賞問題も一発で解決できる**ことです。人間が何時間も悩むような超難問でも、コンピュータにとっては0.01秒もかからずに終了する作業です。

Algorithm X (Dancing Links)は、数独ソルバーにおいて「最強・最速」の一つとされるアルゴリズムです。圧倒的な速度で、確実に解を求めることができます。

### ソルバーの使い分け

Geminiとの会話で、ソルバーには2つのアプローチがあることを学びました：

1. **バックトラッキング法（探索アルゴリズム）**: Algorithm X (Dancing Links)のような、コンピュータが最も得意とする方法。総当たりで全ての可能性を調べる「深さ優先探索（DFS）」の一種。

2. **論理的解法アルゴリズム（ロジカル・ソルバー）**: 人間が数独を解く時に使う「テクニック」をプログラム化したもの。問題の難易度を測るために使われる。

今回実装したAlgorithm X (Dancing Links)は、**「解の存在」や「唯一解」を確認する**用途には最適です。圧倒的な速度で、問題生成時に何万回と「唯一解チェック」を行う用途に最適です。

一方、**「面白い問題（難易度設定）」を作りたい**場合は、ロジカルソルバーが必要になります。DLXは単なる超高速な総当たりなので、その問題が「初級」なのか「プロ級」なのかを判別できません。

## 学んだこと

Day15の開発を通じて、以下のことを学びました：

### Algorithm X (Dancing Links)の強力さ

- **圧倒的な速度**: どんな難問でも瞬時に解くことができる
- **確実性**: 人間には到底不可能な超難問でも、論理的な詰まりに関係なく瞬時に答えを出せる
- **実装の複雑さ**: 双方向リンクリストを使った高度なデータ構造が必要

### 問題生成の難しさ

- **唯一解の確認**: 問題を作るには、ソルバーを何回も呼び出して有効な問題かを確認する必要がある
- **計算コスト**: 1つの問題を生成するために、何百回、何千回とソルバーを呼び出す必要がある
- **難易度の判定**: 問題の難易度を判定するには、ロジカルソルバーが必要

### 実用的なアプリの構成

- **2つのソルバーの使い分け**: 
  - DLXソルバー: 問題を高速に自動生成したり、ユーザーが入力した問題に答えがあるか一瞬で判定したりするために使う
  - ロジカルソルバー: 生成した問題が「どのテクニックを使えば解けるか」を解析し、難易度をラベル付けするために使う

### Geminiとの対話の価値

- **アルゴリズムの理解**: Geminiに相談することで、数独の問題生成アルゴリズムについて深く理解できた
- **実装方針の決定**: 問題を作るよりも解く方が簡単だと分かったことで、実装方針を明確にできた
- **技術的な洞察**: ソルバーの使い分けなど、実用的なアプリを作る上で重要な知識を得られた
